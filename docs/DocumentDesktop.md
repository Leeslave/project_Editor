# 003 공통 데스크탑

작성: 2026-09-10. 상태: UI 구현·씬 호스트 연결 완료, 실행/시각 검증 및 게임 컨트롤러 연결 대기. 테스트·빌드·Unity 플레이를 실행하지 않았다.

## 화면과 창

기존 uGUI/TMP와 프로젝트의 neodgm 글꼴을 사용한다. 논리 화면 1600×960(5:3)을 화면 안에 균등 축소/확대하고 여백은 검정으로 처리한다. 좌측 1280×960(4:3), 우측 320×960의 고정 업무 패널을 두어 가로 비율 4:1을 유지한다. 최종 지원 해상도/최소 글자 크기 정책은 009에서 결정한다.

일반 모드는 회색 배경과 진술 파일/실제 행동 폴더, 극비는 검정 배경과 인물 폴더 및 빨간 CONFIDENTIAL 표시를 사용한다. 우측 날짜·지정 대상·업무 지시는 스크롤되며 진행 상태와 제출 영역은 고정된다. 시간 제한은 없다.

파일 탐색기와 각 문서는 별도 창이다. 스크롤 문장 버튼과 프로필 문자열 입력을 제공한다. 창 제목을 끌면 Canvas 좌표로 이동하며 작업 패널·작업표시줄·워터마크 영역까지 넘어가지 않는다. 최소화한 창은 작업표시줄에서 복원한다. 열린 파일을 다시 누르면 기존 창을 앞으로 가져오므로 새 열람 사건이 생기지 않는다. 작업표시줄 항목이 넘치면 가로 스크롤로 접근한다.

창의 X는 뷰만 제거한다. 수정 사본·조사 기록·열람 이력은 DocumentDesktop의 별도 상태에 남으며 파일을 다시 열면 해당 상태를 표시한다. 원본 콘텐츠와 입력 상태는 Initialize에서 복사하므로 Name 변경으로 인물 ID나 원본이 바뀌지 않는다. 같은 인물/날짜의 진술과 행동 각각 1개를 선택하며 다른 대상/날짜를 선택하면 기존 선택을 지운다.

## 파일별 책임

| 파일 | 책임 |
| --- | --- |
| DocumentDesktopUI | TMP·패널·버튼·스크롤·작업표시줄 생성과 공통 색상 |
| DocumentDesktopWindow | 창 포커스와 영역 내 위치 제한 |
| DocumentWindowDrag | 포인터 좌표를 작업 영역의 로컬 좌표로 변환 |
| DocumentDesktop | 문서 표시, 창 목록, 수정 사본, 선택/열람 이벤트와 진행 표시 |
| DocumentDesktopHost | 씬 연결, 기존 화면 활성 상태 보존, 명시적 콘텐츠/상태 전달, 미리보기 |

기존 Windows_M/UIICons는 고정 풀과 DB_M의 첨부 흐름에 의존하고, UIDragger는 Camera.main 기반 월드 좌표, MinimumButton_D는 Transform 이동, Tabs_D는 단일 GetOptionFile 편집기에 연결돼 있다. 여러 독립 문서창의 수명·Canvas 좌표를 다루기 위해 새 공통 창 컴포넌트를 만들었다. 기존 클래스/씬 연결은 삭제하지 않았다. 새로운 UI 프레임워크나 외부 패키지는 추가하지 않는다.

## 기존 씬 연결과 미리보기

`Assets/Scenes/Minigame/Document.unity`에 DocumentDesktopHost를 추가했다. 기본 진입 시 기존 게임은 그대로 실행된다. 004/005 컨트롤러가 `host.Show(assignment, playState, portraitAssets)`를 호출하면 검증된 새 UI를 생성하고 레거시 루트들을 비활성화한다. `Close()`는 상태 스냅샷을 반환하고 기존 루트 활성 상태를 복원한다. 같은 세션 재진입 때 새 Begin을 호출하지 않고 반환/보관한 상태를 전달한다.

**현재 기존 업무 실행 경로에서 Show를 호출하는 컨트롤러는 아직 없다.** 003은 공통 UI와 연결 지점의 구현이며 실제 플레이가 새 UI로 전환되었다는 뜻은 아니다. 출시 일차에 PDF 샘플을 임의 배치하지 않았다. 업무 코드/Stage/TargetDateId에 맞는 실제 콘텐츠 선택과 세션 공급은 004–007의 연결 작업이다.

독립 `Assets/Scenes/Minigame/DocumentDesktopPreview.unity`는 기존 게임 서비스 없이 새 UI를 생성한다. 실행 후 Host 컴포넌트의 컨텍스트 메뉴 `Preview/Statement Check`, `Preview/Forgery`로 모드를 바꿀 수 있다. 모드별 수정 사본은 전환 중 보존한다. 메뉴는 Play 상태에서만 작동한다. 미리보기는 빌드 씬 목록에 추가하지 않았다.

`Assets/Resources/DocumentDesktopPreview.json`은 002 계약 예시의 복사본이다. 초상화는 키와 Sprite 매핑을 Show에 제공하면 표시하며 미제공 시 사진 없음으로 표시한다. 샘플은 대표 문장만 포함한다. 게임 업무 완료/평판/세이브를 변경하지 않으며 기록/제출 컨트롤러를 흉내 내지 않는다. 따라서 미리보기의 기록하기·제출 버튼은 비활성이다.

## 후속 API 계약

- `DocumentOpened(ViewRecord)`: 닫힌 파일을 새로 열 때만 발생. 지정 인물+날짜 여부와 지속 가능한 사건 ID를 제공한다. 최소화 복원/포커스 이동은 제외한다. Submitted 이후 열람은 사건을 만들지 않는다.
- `PairSelectionChanged(statementId, actionId)`: 현재 선택 쌍. 취소는 둘 다 null이며 점수를 변경하지 않는다.
- `RecordRequested`: 둘 다 선택되고 핸들러가 연결돼 있을 때 기록 버튼 활성. 004가 정답 판정 후 UpdateInvestigation으로 결과를 전달한다.
- `ProfileChanged(personId, field, value)`: 문자열 수정 사본을 갱신한 후 발생. IME·포커스 전환의 실제 동작 검증 및 최종 채점은 005에서 수행한다.
- `UpdateInvestigation`: 004가 계산한 기록/조사완료 상태를 반영한다. 완료된 대상의 추가 수정은 거부하고 문장 선택을 비활성화한다. 조사완료 명령과 최소 기록/누락 검증 자체는 004 책임이다.
- `SubmissionRequested`: 실제 제출 핸들러가 연결되고 제출 가능한 상태일 때만 발생한다. 극비는 기본 제출 가능, 일반은 전체 조사완료 후 가능하다. `SetSubmissionAllowed`로 컨트롤러가 추가 조건을 반영할 수 있다.
- `LockSubmission`: 제출 이후 문장 선택과 프로필 입력을 잠근다. 결과 판정·평판 적용·업무 완료를 수행하지 않는다.
- `GetStateSnapshot`: 내부 수정 사본과 열람/조사 상태의 깊은 복사본을 반환한다. 006/007은 이벤트 처리 결과와 함께 세션에 보관하며, 실제 실행 경계에서 ValidateForExecution을 호출하고 영속 중복 방지 이력을 관리해야 한다.

003에서 생성한 창 상태를 그대로 세이브 형식으로 사용하지 않는다. 창 좌표·최소화·선택은 화면 임시 상태이며, 기록/입력값은 플레이 상태다. 영속 사건 적용과 업무 ID 생성은 006/007에서 구현한다.

## 정적 확인 범위

씬에 추가한 Host의 스크립트 GUID, 글꼴/미리보기 TextAsset 참조와 기존 루트 fileID를 원본 자산과 대조했다. 기존 씬 변경은 Host 루트 추가이며 기존 UI 오브젝트를 편집하지 않았다. 변경 파일의 공백 오류를 확인했다. 실제 컴파일·화면 배치·입력·스크롤·IME·해상도 변경의 성공 여부는 아직 검증하지 않았다.

## 커밋 전 구조·주석 점검 (2026-09-10)

- 제출의 모드별 완료 조건과 컨트롤러의 추가 허용 조건을 분리했다. SetSubmissionAllowed(true)는 미완료 조사를 우회하지 않으며, UpdateInvestigation은 외부의 제출 금지를 덮어쓰지 않는다. 클릭 콜백에서도 현재 조건을 재확인한다.
- 복원 상태의 null 목록·잘못된 단계·중복/누락 인물·조사 대상 불일치를 UI 생성 전에 거부한다. 기록 정답 검증과 세이브 마이그레이션은 별도 컨트롤러 책임이다.
- 사용하지 않는 창 본문 사전을 제거하고 문서 ID 사전 조회를 사용한다. 닫힌 창의 문장 버튼 참조도 제거한다.
- 명시적 Close와 씬 파괴 정리를 분리했다. 파괴 중에는 레거시 스크립트를 재활성화하거나 버릴 스냅샷을 직렬화하지 않는다.
- 제출 허용·복원 검증·뷰 파괴 주석을 실제 책임과 동작에 맞췄다. 표시/상태/호스트 분리는 유지하며, 실제 판정과 영속 저장은 004–007 범위다.
- 다음 단계 전에는 Unity 컴파일 확인과 미리보기의 두 모드, 창 이동/복원/재열람, 입력 보존, 긴 문서 스크롤을 수동 확인하는 것이 권장된다. 이번 점검에서는 실행하지 않았다.
