# 일반·기밀 업무 통합 TEST

`Assets/Scenes/Minigame/WorkIntegration_TEST.unity` 하나만 열고 Play 한다.
MainController 또는 DirectPlayController를 함께 열지 않는다.

## 실행 흐름

| 업무 | 경로 | 사용 콘텐츠 |
| --- | --- | --- |
| 일반 문서 | 선택 → Document_TEST | 문서 리메이크의 Document Stage_0 |
| 기밀 문서 | 선택 → 인증 안내 → Maze_TEST → Document_TEST | 문서 리메이크의 SecureDocument Stage_0 |
| 일반 암호 | 선택 → 기존 ADFGVX_TEST | 기존 복호화 Stage 6 |
| 기밀 암호 | 선택 → 인증 안내 → Maze_TEST → 기존 ADFGVX_TEST | 기존 복호화 Stage 12 |

Document_TEST는 본편 Document 씬에 연결된 호스트·일반 대조·기밀 수정 컨트롤러와 스킨 참조를 복사해 사용한다.
Document_TEST 또는 Maze_TEST를 단독으로 열어도 같은 업무 선택 메뉴에서 시작한다.
기존 ADFGVX_TEST의 단독 실행은 종전의 자유로운 과제·암복호화 선택과 튜토리얼을 유지한다.
통합 호스트가 ADFGVX_TEST를 열면 선택한 복호화 과제로 고정된다.
기본으로 기존 암호 튜토리얼이 자동 시작하며, 업무 메뉴의 튜토리얼 설정으로 끌 수 있다.

## 튜토리얼

- 첫 Play에 업무 종류, 기밀 인증, 제출/중단을 설명하는 3장 안내가 나온다.
- `안내 없이 시작`으로 건너뛰거나 업무 메뉴에서 튜토리얼을 켜고 끈다.
- 미로는 소개 → 실제 이동 → 토큰 확보 → EXIT 이동 → 현재 업무 접근 승인 순서로 안내한다.
  안내 중에는 타이머가 멈추며, 안내를 끄면 남은 시간으로 일반 인증을 진행한다.
  튜토리얼의 승인 설명에서 `업무 열기`를 누르면 원래 업무로 연결된다.
- 일반 문서는 지정 파일 열기 → 진술/행동 선택 → 기록 → 대상별 조사 완료 → 제출 → 결과 확인을 안내한다.
  모순의 정답을 대신 고르거나 기록하지 않는다. 추가 기록은 자유롭게 할 수 있다.
- 기밀 문서는 지정 프로필 열기 → 지시된 항목 직접 입력 → 입력 확정 → 제출 → 결과 확인을 안내한다.
  입력 중에는 단계를 넘기지 않고, IME/end-edit 확정 후 실제 수정 여부를 관찰한다.
  입력의 정확도는 기존 규칙대로 제출 시 판정한다.
- 문서 안내는 위쪽 별도 공간에 표시하며 실제 조작 대상을 테두리로 강조한다.
  최소화/닫힌 문서를 다시 열도록 안내하고, 긴 파일은 기존 스크롤을 사용한다.
- 각 게임 안에서도 안내를 끄거나 다시 켤 수 있다. 기존 작업 내용은 초기화하지 않는다.
- 튜토리얼은 접근권·정답·업무 완료를 자동으로 부여하지 않는다.

## 인증과 결과

- 인증은 이동 → 접근 토큰 하나 확보 → EXIT 진입 방식이다. 방향키/WASD 또는 화면 방향 버튼으로 이동한다.
- 고정 맵 2개를 업무별로 지정했다. 제한 시간은 35초이며 시간 초과 후 안내 화면에서 다시 시도한다.
- 토큰만 얻거나 토큰 없이 EXIT에 도착해서는 인증에 성공하지 않는다.
- 승인 문구를 약 0.8초 표시한 뒤 원래 선택한 업무로 자동 연결한다.
- 인증 성공은 업무 완료가 아니다. 다음 기밀 업무에는 새 인증이 필요하다.
- 인증 중단/업무 중단은 완료로 기록하지 않는다. 다시 선택하면 새 실행으로 시작한다.
- 문서는 기존 제출·채점·평판 정산을 사용한다. 정확도와 제출 완료 여부는 구분한다.
- 암호는 정답을 제출한 뒤 해독 결과를 확인하고 `업무 목록`으로 돌아간다.
- 각 화면의 업무 목록/중단 버튼 또는 F10으로 복귀한다. 중단 시 입력은 폐기된다.
- 업무 ID와 실행 ID를 분리한다. 이전 실행의 인증 콜백이나 다른 업무의 완료 요청으로 현재 업무를 완료할 수 없다.
- 테스트 평판·완료 이력은 메모리에만 보관한다. 본편 저장 파일은 읽거나 쓰지 않는다.

## 범위

이번 변경은 TEST 씬에서 네 업무와 미로 인증을 연결한 프로토타입이다.
본편 날짜별 업무 편성, 스토리 이벤트, 영구 기록/복기는 별도 단계다.
닷지는 이번 인증 경로에 포함하지 않았다.
기존 문서의 선행 Maze/Dodge 완료 조건은 본편 경로에서 유지된다.
통합 TEST에서는 과거 완료 이력 대신 현재 실행의 인증 권한을 검사한다.

WorkIntegrationTest 컴포넌트의 Assignments에서 업무 ID, 종류, 등급, 스테이지, MazeLayout(0 또는 1)을 설정한다.
ADFGVX에는 기존 데이터에 존재하는 복호화 스테이지(6, 12)를 지정한다.

## 검증

PowerShell에서 `./Tools/WorkIntegrationValidation/Validate.ps1`을 실행한다.
설치된 Unity 2021.3.45f2의 엔진/TMP/uGUI 및 프로젝트의 기존 ScriptAssemblies를 참조하여,
새 호스트·뷰·상태 모델과 문서/암호 리메이크 코드를 컴파일한다.
상태 검증은 실제 WorkExecution/ShortMaze/문서·미로 튜토리얼 모델을 사용한다.
네 가지 업무, 인증 실패·재시도·중단·업무 간 격리, 중복 완료, 맵의 토큰/출구 경로,
씬 스크립트 GUID와 빌드 등록, 실제 조작에 따른 안내 전환, 관찰 중 업무 상태 불변,
입력 확정 전 단계 유지와 문서 재열람 복구를 검사한다.
`./Tools/AdfgvxValidation/Validate.ps1`로 기존 암호 과제와 튜토리얼 회귀를 검사한다.

이 검사는 Unity의 실제 프레임 실행·포인터 입력·시각 검증을 대체하지 않는다.
현재 환경에서는 Unity 배치 실행이 라이선스 클라이언트 연결 실패(종료 코드 199)로 종료되었다.
Unity Play에서 네 업무 전체, 인증 시간 초과와 재시도, 인증/업무 중단, 문서의 IME 입력,
암호 제출 후 결과 확인과 목록 복귀를 최종 확인해야 한다.
