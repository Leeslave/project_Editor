# 1일차 출근 안내

복도의 클로버 대화(`day 1/[1-1] 오전 복도.json`)가 완전히 끝난 뒤, 복도 화면에 있는 정보 1반 출입문을 강조해 클레이튼이 반장으로 근무하는 일터임을 설명한다. 이동 화살표가 닫혀 있으면 이동 버튼 안내를 먼저 표시한다. 설명은 화면 클릭으로 넘기고 실제 출입 화살표를 눌러 입장한다. 입장 후 자동으로 시작되는 사무실 담화 중에는 조명을 종료하며, 이후 기존 자리 이동·단말기 안내로 이어진다. 출입 안내 완료 상태는 같은 날짜의 씬 이동 중에는 유지하고 날짜를 다시 선택하면 초기화한다.

`MainWorld.unity`의 `First Day Commute Tutorial`이 Day 1, 아침 시간대 0에서 동작한다. 아침 라디오/집 대화가 열렸다가 닫힌 것을 확인한 뒤 거리 0에서 시작하므로 라디오나 선택지 위에 안내가 겹치지 않는다. 다른 날짜 및 시간대에서는 시작하지 않는다.

0일차에서 시작한 경우에도 대기 코루틴을 유지해 1일차 아침까지 기다린다. 0일차 대화는 아침 대화로 세지 않으며, 1일차 아침을 지난 뒤에는 대기를 종료한다. 0일차 월터의 마지막 대사에는 `Walter_!` 배경을 유지해 월드의 길거리가 드러나지 않게 한다.

기존 `Tutorial_Shader/TutorialSet.prefab`, `TutorialController`, `TutorialBorder`의 조명 마스크와 설명 카드를 재사용한다.

1. 기존 이동 화살표가 켜져 있으면 먼저 닫고 이동 버튼을 강조한다. 클릭하면 기존 `WorldSceneManager.SwitchInteraction`이 화살표를 연다.
2. 회사 앞 방향의 실제 `Door`를 강조한다. 클릭하면 기존 `Door.OnPointerClick`과 위치 서비스로 Street 1에 이동한다.
3. 회사 앞에서 정보국, 복도, 정보 1반, 업무 단말기의 관계를 설명한다. 화면을 클릭하면 출입 안내로 이어진다.
4. 회사 출입문을 강조한다. 클릭하면 Hallway 0으로 진입하고 안내가 종료된다. 기존 복도 대화가 이어진다.

이동을 자동 완료하거나 시간대를 변경하지 않는다. 튜토리얼 입력을 기존 이동 동작에 전달하고, 강조 밖 클릭으로 이동 단계를 건너뛸 수 없게 한다. 회사 설명은 아무 곳이나 눌러 넘긴다. 기본 템플릿의 마스크 좌표 계산은 Overlay/Camera Canvas를 구분하도록 보완했다.

1일차 시간대 1에는 같은 호스트의 `FirstDayWorkstationTutorial`이 사무실의 더 킹 담화 및 후속 대화가 끝나기를 기다린다. `ChatTrigger`가 대화 원본 경로를 전달하고 `Chat.LastCompletedDialogueSource`가 해당 대화 전체의 종료를 기록한다. 정확히 `day 1/[1-1] 오전 사무실.json`이 종료되어야 안내를 시작하므로 복도나 다른 NPC 대화 종료로는 시작하지 않는다. 이후 이동 버튼(화살표가 닫혀 있을 때만), 입구(Office 0)에서 안쪽(Office 1)으로 가는 화살표, 안쪽에서 내 자리(Office 3)로 가는 화살표, 기존 사원증 대화, 스크린 접속 순으로 실제 대상을 강조한다. 이동 대상 화살표는 목적지와 출발 화면의 좌표를 함께 확인한다. 사원증 대화 중에는 다음 안내를 띄우지 않는다.

`Screen_TEST`의 `RetroScreenDesktop.Start`는 `FirstDayScreenTutorial`을 연결한다. 전원이 꺼져 있으면 전원 버튼을 강조하고, 부팅 및 씬 전환 완료 후 업무 단말 → 수신함 → 메일 본문 → 메신저 → 연락 확인 → 신문 → 신문 설명 → 프로그램 → 메뉴 설명 → 전원/재부팅 → 업무 지원 → 업무 실행 방법 순으로 안내한다. 프로그램 버튼 단계는 해당 버튼 클릭을 요구하며, 설명 단계는 화면 클릭으로 넘긴다. 마지막에는 업무 지원 창을 열어 두고 입력을 반환한다. 이미 켜진 단말기는 전원 단계를 생략한다.

리메이크 단말기에서는 기존 `R_ScreenTutorial`의 팝업과 입력 차단막을 숨겨 안내 중복을 막는다. 화면 안내는 독립된 루트 Canvas를 사용하며 `Resources/Tutorial/FirstDaySpotlight.prefab`의 기존 조명 마스크와 한글 글꼴을 재사용한다. `FirstDayOnboarding`은 씬 사이의 완료 상태를 유지하고 `DayController.Init`에서 초기화하므로, 업무 복귀나 재부팅 시 반복하지 않고 날짜를 다시 선택하면 다시 안내한다. 저장 파일 형식은 변경하지 않는다.

`Tools/Tutorial/Build First Day Commute`는 현재 MainWorld를 읽고 출근 안내 오브젝트를 다시 구성한다. `Tools/Tutorial/Verify First Day Commute`는 DirectPlay의 메모리 전용 저장 서비스로 아침 대화를 종료하고 조명 마스크에 실제 포인터 이벤트를 전달해 거리/복도 이동을 검사한다. 플레이어 저장 파일의 전후 해시를 비교하며, 검증 후 Play를 종료하고 이전 씬으로 복귀한다. 결과와 미리보기는 `output/commute/`에 저장한다.

`Tools/Tutorial/Verify Day Zero To First Commute` (`Ctrl+Shift+F10`)는 0일차부터 일반 대사 넘기기로 월터의 마지막 배경을 확인하고, 실제 `NEXTDAY` 액션으로 1일차에 진입한 뒤 같은 출근 검증을 수행한다. 날짜별 원본 데이터를 읽고 플레이어 저장 파일에는 기록하지 않는다.

업무 화면은 `ScreenSceneRoute.Name = "Screen_TEST"`를 공통 진입점으로 사용한다. 단말기 클릭, 문서 제출 후 복귀, 암호 튜토리얼/암호 업무 완료, 미로 및 기타 기존 미니게임 복귀 경로를 함께 변경했다. 원본 Screen의 UI는 보존한다.
